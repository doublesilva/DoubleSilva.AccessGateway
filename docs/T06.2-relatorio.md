### 1.1 "API health pela LAN" (`https://casa.home/api/health` → 404)

| Data | `casa.home` |
| --- | --- |
| até 27/09 (`Caddyfile.bak-before-outhome`) | `handle /api/health` e `handle /api/*` → API `127.0.0.1:5100`; resto → dashboard |
| desde 27/09–03/10 (`Caddyfile.bak.20261003-161852` e atual) | `reverse_proxy 127.0.0.1:5300` = **OutHome** |

O OutHome (React/Vite + BFF ASP.NET, `src/HomeAutomation.OutHome/Program.cs`) mapeia
`app.Map("/api/{**path}", () => Results.NotFound())`: o 404 é **por desenho**, porque a API deixou de ser publicada pelo
gateway. Ela escuta só em `127.0.0.1:5100`, e seu endpoint de saúde real é `/health`
(`{"status":"healthy",…}`, HTTP 200). O OutHome não tem endpoint de saúde: `/health`, `/status` etc. devolvem o
`index.html` do SPA (fallback, 200), o que não serve como prova de vida.

### 1.2 "API health pelo Tailscale" (mesma URL pelo IP do Tailscale → 404)

A mesma causa do item 1.1.

### 1.3 "Blazor negotiate via Tailscale" (`POST https://panel.home/_blazor/negotiate` → 301)

| Data | `panel.home` |
| --- | --- |
| até 25/09 | `reverse_proxy 127.0.0.1:5200` (Panel) |
| desde 25/09–27/09 | `redir https://panel.home.doublesilva.com{uri} permanent`; o domínio novo fica atrás do Authelia (`forward_auth`), exceto `/stream/*` |

O Panel ainda é Blazor Server (`MapRazorComponents<App>().AddInteractiveServerRenderMode().RequireAuthorization()`),
com um frontend React em `/react*`. O negotiate exige autenticação: sem sessão, o desafio padrão do Panel é OIDC, que
cria um pedido PAR no Authelia a cada chamada. Por isso ele **não** pode ser usado por um monitor anônimo a cada 5 min.
A exceção é `/stream/*`: o desafio usa o cookie e responde 401.
