# CA interna do home-server — instalação, verificação e renovação nos dispositivos

Os sites internos (`*.home.doublesilva.com`, `casa.home`, `panel.home` etc.) usam certificados emitidos pela **CA
interna do DoubleSilva.AccessGateway**. Para o navegador ou o aplicativo aceitar esses sites sem aviso, o dispositivo
precisa **confiar na raiz** dessa CA. A instalação é feita uma vez por dispositivo (ou perfil) e vale até 2036.

> **Nunca** contorne um aviso de certificado ("Avançado → continuar assim mesmo", `-k`, "verificar SSL: não"). Se o
> aviso aparecer num dispositivo que já confia na raiz, **algo está errado** (§7).

## 1. Identificação da raiz (confira SEMPRE antes de instalar)

| Campo | Valor |
| --- | --- |
| Nome (assunto e emissor) | `CN=Caddy Local Authority - 2026 ECC Root` |
| **Fingerprint SHA-256 do certificado** | **`AD:F8:85:14:FF:96:F1:71:93:E3:84:90:8F:A4:43:42:FE:7F:62:48:53:79:32:14:44:A8:8C:B2:D9:C2:38:56`** |
| Fingerprint SHA-1 (só para telas que mostram SHA-1, como o "Impressão digital" do Windows) | `E5:E3:ED:3D:65:FD:C3:3B:F7:1A:C4:C2:CD:EF:9F:BE:9C:2A:85:E7` |
| Número de série | `DDB9BB651CECD7B0CF430BC9CEEB8A72` |
| Validade | 18/09/2026 → **27/07/2036** |
| Chave | ECC P-256; `CA:TRUE, pathlen:1` |
| Arquivo distribuído | `caddy-root.crt` (PEM, 631 bytes); SHA-256 **do arquivo**: `d8b4fbc24ce61f302da955a2875dfd43bf80f3d896d893ccb60be0fc4c7a80d7` |

**Fingerprint ≠ hash do arquivo.** O fingerprint é calculado sobre o certificado (DER) e é o que os sistemas mostram.
O hash do arquivo só serve para conferir o `.crt` baixado com `sha256sum`/`Get-FileHash`. Os dois valores acima são
oficiais.

**Canal confiável para o fingerprint:** este documento no repositório (acessado por HTTPS autenticado), a anotação no
KeePassXC ou uma cópia impressa. **Não** confie num fingerprint obtido pela mesma via do download (`cert.home`).

## 2. Download

```text
http://cert.home/caddy-root.crt
```

- O endereço é **HTTP de propósito**: um dispositivo que ainda não confia na CA não conseguiria abrir uma página
  HTTPS dela. **HTTP não autentica a origem**: qualquer um na rede poderia, em tese, entregar outro arquivo. Por isso a
  conferência do fingerprint (§1) é **obrigatória**.
- O endereço só funciona na LAN ou no Tailscale (o DNS interno resolve `cert.home` para o servidor).
- O servidor só entrega esse arquivo; qualquer outro caminho dá 404.

## 3. Instalar como CA confiável × apenas importar

- **Importar** um certificado só o guarda (por exemplo, em "Outras pessoas" ou "Certificados intermediários"). Os
  sites **continuam com aviso**.
- **Instalar como CA raiz confiável** coloca o certificado no repositório de autoridades em que o sistema confia para
  identificar sites. **É isso que é necessário.** Cada seção abaixo indica o passo que dá a confiança (em geral, um
  segundo passo explícito).
- Confie **só nesta raiz**, só para identificar sites, e **só nos seus dispositivos**. Quem controla a chave da CA pode
  emitir certificado para qualquer domínio que esses dispositivos aceitarão. A chave fica protegida no servidor e no
  backup cifrado; nunca a copie para um dispositivo.

## 4. Procedimentos por plataforma

Os menus mudam entre versões. Os nomes abaixo são os mais comuns.

### 4.1 Windows 10/11 (Chrome, Edge e outros que usam o repositório do Windows)

Interface:

1. Baixe `caddy-root.crt`.
2. Confira o fingerprint: abra o arquivo → aba **Detalhes** → **Impressão digital** (é SHA-1: `E5:E3:ED:…:85:E7`),
   ou use o PowerShell abaixo para o SHA-256.
3. **Instalar certificado…** → **Usuário Atual** (só você) ou **Máquina Local** (todos; exige administrador) →
   **Colocar todos os certificados no repositório a seguir** → **Autoridades de Certificação Raiz Confiáveis** →
   Concluir → confirme o aviso de segurança, que mostra a impressão digital.

Linha de comando:

```powershell
# fingerprint SHA-256 (sem ":"; Windows em inglês: "Cert Hash(sha256)", em português: "Hash Cert(sha256)")
certutil -dump .\caddy-root.crt | Select-String 'Cert Hash\(sha256\)|Hash Cert\(sha256\)'   # adf88514ff96f171…2d9c23856
# alternativa (PowerShell 7):
[System.Security.Cryptography.X509Certificates.X509Certificate2]::new("$PWD\caddy-root.crt").GetCertHashString('SHA256')
certutil -user -addstore Root .\caddy-root.crt                            # usuário atual (abre confirmação)
# todos os usuários (PowerShell como administrador): certutil -addstore Root .\caddy-root.crt
```

Verificar: `certmgr.msc` (usuário) ou `certlm.msc` (máquina) → Autoridades de Certificação Raiz Confiáveis →
Certificados → "Caddy Local Authority - 2026 ECC Root".

### 4.2 macOS (Safari, Chrome, Edge)

```sh
openssl x509 -in caddy-root.crt -noout -fingerprint -sha256      # confira com §1
# só o seu usuário (pede a sua senha):
security add-trusted-cert -r trustRoot -k ~/Library/Keychains/login.keychain-db caddy-root.crt
# todos os usuários:
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain caddy-root.crt
```

Pela interface: abra o arquivo → **Acesso às Chaves** (chaveiro "início de sessão") → abra o certificado →
**Confiar** → "Ao usar este certificado": **Confiar Sempre** → feche e confirme com a senha. Só importar deixa o
certificado como "não confiável".

### 4.3 Ubuntu / Debian e derivados (sistema, curl, Python, ferramentas)

```sh
openssl x509 -in caddy-root.crt -noout -fingerprint -sha256      # confira com §1
sudo install -m 644 caddy-root.crt /usr/local/share/ca-certificates/doublesilva-caddy-root-2026.crt
sudo update-ca-certificates                                       # deve indicar "1 added"
```

Fedora/RHEL: copie para `/etc/pki/ca-trust/source/anchors/` e rode `sudo update-ca-trust`.

Chrome/Chromium no Linux usam o banco NSS do usuário, não o do sistema:

```sh
sudo apt install libnss3-tools
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "DoubleSilva Caddy Local Authority 2026" -i caddy-root.crt
certutil -d sql:$HOME/.pki/nssdb -L | grep -i doublesilva
```

### 4.4 Android

1. Baixe `caddy-root.crt` no navegador (LAN ou Tailscale).
2. Confira o fingerprint: em muitas versões, a tela de instalação ou os detalhes do certificado instalado
   (Configurações → … → Credenciais do usuário) mostram o SHA-256. Se a versão não mostrar, confira o arquivo num
   computador (`sha256sum` = `d8b4fbc2…`) e copie o mesmo arquivo para o telefone.
3. **Configurações → Segurança e privacidade → Mais configurações de segurança → Criptografia e credenciais → Instalar
   um certificado → Certificado de CA** → aceite o aviso → escolha o arquivo.

Limitações:

- O Chrome e os navegadores do sistema confiam em CAs do usuário.
- **Muitos aplicativos (Android 7+) não confiam em CAs instaladas pelo usuário**, a menos que o próprio app permita.
  Se um app recusar o certificado, a solução é o app oferecer suporte, **não** desligar a verificação.
- O Firefox para Android tem configuração própria (§5).

### 4.5 iOS / iPadOS

1. Abra `http://cert.home/caddy-root.crt` no **Safari** → "Este site está tentando baixar um perfil" → **Permitir**.
2. **Ajustes → Perfil Baixado → Instalar**. Antes de confirmar, toque em **Mais detalhes** e confira o **SHA-256** com
   §1.
3. **Passo obrigatório para confiar:** **Ajustes → Geral → Sobre → Ajustes de Confiança de Certificados** → ative
   **confiança total** para "Caddy Local Authority - 2026 ECC Root". Sem isso, o perfil fica só "instalado".

### 4.6 Home Assistant (192.168.0.166)

- **Acesso ao Home Assistant pelo navegador** (`https://ha.home.doublesilva.com`): quem precisa confiar é o
  **dispositivo do usuário** (§4.1–4.5), não o Home Assistant.
- **Aplicativo Companion**: usa o repositório do sistema do celular (no Android vale a limitação de CAs do usuário em
  §4.4).
- **O próprio Home Assistant como cliente HTTPS** dos sites internos (integrações que chamam `*.home.doublesilva.com`):
  o Home Assistant OS **não oferece uma forma suportada e persistente** de acrescentar uma CA ao repositório do core.
  Se isso for necessário, abra uma tarefa específica para avaliar cada integração (algumas aceitam um arquivo de CA) ou
  a instalação em container com a CA montada. **Não** use `verify_ssl: false`.

## 5. Navegadores com repositório próprio

| Navegador | Comportamento | O que fazer |
| --- | --- | --- |
| Chrome / Edge (Windows, macOS) | usam o repositório do sistema | §4.1 / §4.2 |
| Chrome / Chromium (Linux) | banco NSS do usuário | §4.3 (certutil) |
| Safari | repositório do sistema | §4.2 / §4.5 |
| **Firefox** (todas as plataformas) | **repositório próprio** | Configurações → Privacidade e Segurança → Certificados → **Ver certificados** → **Autoridades** → **Importar** → marque **"Confiar nesta CA para identificar sites"**. Alternativa no Windows e no macOS: em `about:config`, `security.enterprise_roots.enabled = true` faz o Firefox aceitar as raízes instaladas no sistema |
| Firefox para Android | próprio | Configurações → Sobre o Firefox → toque 5 vezes no logotipo → em Configurações, ative **"Usar certificados de terceiros"** (passa a usar as CAs do usuário do Android) |

## 6. Verificar se ficou certo

- Abra `https://panel.home.doublesilva.com`: o cadeado deve aparecer **sem aviso**. Nos detalhes do certificado, a
  cadeia é **site → "Caddy Local Authority - ECC Intermediate" → "Caddy Local Authority - 2026 ECC Root"**.
- Linha de comando (Linux/macOS/WSL):

  ```sh
  echo | openssl s_client -connect panel.home.doublesilva.com:443 -servername panel.home.doublesilva.com -CAfile caddy-root.crt 2>/dev/null | grep 'Verify return code'
  # esperado: Verify return code: 0 (ok)
  curl -sS -o /dev/null -w '%{http_code}\n' --cacert caddy-root.crt https://auth.home.doublesilva.com/api/health   # 200
  ```

## 7. Diagnóstico de erros de certificado

| Sintoma | Causa provável | O que fazer |
| --- | --- | --- |
| `NET::ERR_CERT_AUTHORITY_INVALID` (Chrome/Edge), `SEC_ERROR_UNKNOWN_ISSUER` (Firefox), "Esta conexão não é privada" (Safari) | raiz não instalada **como confiável** neste dispositivo, perfil ou navegador | refazer §4 com o passo de confiança; no Firefox, §5; conferir se foi instalada no **usuário** certo |
| Erro só no Firefox | Firefox com repositório próprio | §5 |
| Erro só num app Android | app não aceita CAs do usuário | limitação do app; não desligar a verificação |
| `ERR_CERT_COMMON_NAME_INVALID` / nome não corresponde | o endereço digitado não é um nome servido pelo gateway (por exemplo, IP direto) | usar o nome (`panel.home.doublesilva.com`), não o IP |
| `ERR_CERT_DATE_INVALID` | relógio do dispositivo errado (os certificados dos sites valem 12 h e são renovados sozinhos) | acertar a data e a hora (sincronização automática) |
| Aviso aparece **de repente** num dispositivo que já funcionava | outra CA respondeu (rede errada, interceptação), raiz trocada no servidor ou dispositivo restaurado sem a raiz | **não prossiga**; confira o emissor e o fingerprint da raiz na cadeia contra §1; avise o responsável |
| `openssl … Verify return code: 20` | raiz não informada / não confiada (`-CAfile` ausente) | usar `-CAfile caddy-root.crt` ou instalar no sistema |
| `cert.home` não abre | fora da LAN/Tailscale, DNS sem `cert.home`, ou gateway da Blue em uso (§8) | conectar à rede interna; copiar o arquivo de outro dispositivo e **conferir o fingerprint** |

## 8. Durante um rollback para a Blue

- A Blue usa **a mesma raiz** (mesma CA): **nada muda nos dispositivos**, e os sites continuam sem aviso.
- Durante o rollback, `http://cert.home/caddy-root.crt` **não fica disponível** (a Blue não publica o arquivo e
  responde 404). Quem precisar instalar a raiz nesse período deve copiar o arquivo de outra fonte confiável e conferir
  o fingerprint (§1).

## 9. Rotação futura da raiz (com sobreposição de confiança)

A raiz atual vale até **27/07/2036**. A troca será planejada com antecedência (início até **07/2035**):

1. **Anúncio:** a nova raiz terá outro nome (por exemplo, "…2035 ECC Root") e outro fingerprint, publicados neste
   documento.
2. **Sobreposição (semanas ou meses):** instalar **a nova raiz ao lado da atual** em todos os dispositivos (§4), sem
   remover a antiga. Os sites continuam emitidos pela raiz atual.
3. **Troca no servidor:** em janela controlada, o gateway passa a emitir pela nova raiz. Quem já tem as duas não nota
   nada.
4. **Remoção da antiga:** depois de um período de observação, remover a raiz antiga dos dispositivos (§10).

Durante a sobreposição, `cert.home` publicará as duas raízes (arquivos separados), cada uma com o fingerprint
documentado.

## 10. Remover a confiança (comprometimento ou fim de uso)

Remova **imediatamente** se for avisado de comprometimento da chave da CA, ou se o dispositivo deixar de ser seu.

| Plataforma | Remoção |
| --- | --- |
| Windows | `certmgr.msc` / `certlm.msc` → Autoridades de Certificação Raiz Confiáveis → excluir "Caddy Local Authority - 2026 ECC Root"; ou `certutil -user -delstore Root DDB9BB651CECD7B0CF430BC9CEEB8A72` (sem `-user` para a máquina, como administrador) |
| macOS | Acesso às Chaves → apagar o certificado; ou `sudo security delete-certificate -c "Caddy Local Authority - 2026 ECC Root" /Library/Keychains/System.keychain` (e no chaveiro de início de sessão, sem sudo) |
| Ubuntu/Debian | `sudo rm /usr/local/share/ca-certificates/doublesilva-caddy-root-2026.crt && sudo update-ca-certificates --fresh`; NSS: `certutil -d sql:$HOME/.pki/nssdb -D -n "DoubleSilva Caddy Local Authority 2026"` |
| Android | Criptografia e credenciais → Credenciais do usuário → selecionar → Remover |
| iOS/iPadOS | Ajustes → Geral → VPN e Gerenciamento de Dispositivos → perfil → Remover Perfil |
| Firefox | Ver certificados → Autoridades → selecionar → Excluir ou desconfiar |

Depois de remover, os sites internos voltam a mostrar aviso até uma nova raiz ser instalada. É o esperado.

## 11. Referência para operadores

### Regras

- O fingerprint oficial (§1) vem da PKI da Green e é o mesmo do caminho canônico
  `/etc/accessgateway/ca/caddy-root.crt`. Confira no servidor com
  `sudo /srv/accessgateway/app/scripts/ca-copies-check.sh`.
- `cert.home` só distribui o certificado **público**. A chave (`root.key`) nunca sai da PKI da Green, do backup cifrado
  e do escrow offline.
- Nunca orientar ninguém a ignorar avisos, desligar a verificação de certificado ou instalar a raiz em dispositivos de
  terceiros.
- O monitoramento contínuo (smoke, seção "CA …") acusa qualquer divergência entre as cópias e o `cert.home`.

### Checklist ao orientar um usuário

1. Dispositivo na LAN ou no Tailscale.
2. Baixar `http://cert.home/caddy-root.crt`.
3. **Conferir o SHA-256 com §1 por um canal confiável.**
4. Instalar **como CA raiz confiável** (§4) e no navegador com repositório próprio, se for o caso (§5).
5. Validar com `https://panel.home.doublesilva.com` (§6).

### Em caso de comprometimento da CA

1. Avisar todos os usuários para removerem a raiz (§10).
2. Executar a rotação de emergência (§9 comprimido; `docs/T07.5-relatorio.md` §6).
3. Publicar a nova raiz e o novo fingerprint neste documento e reinstalar nos dispositivos.
